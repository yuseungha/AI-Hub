# AI 작업 허브

Codex·Claude·ChatGPT 작업 결과물을 한곳에서 보는 Windows 데스크톱 앱. 둘러보기·미리보기·검색은 파일을 바꾸지 않음. 복사·이동·휴지통 삭제는 사용자가 확인한 경우에만 실행.

## 이번 변경

- **디자인:** 미리보기 패널 16px 안쪽 여백과 왼쪽 기준선 정렬, 글자 크기 3단계(pt 통일), 작은 창용 두 줄 툴바, 글이 길면 높이가 늘어나는 프로젝트 카드, 목록 행 왼쪽 상태 띠와 상태 칩, 빈 화면 안내 통일.
- **AI 아이콘과 색상:** AI 이름 옆에 Codex·Claude·ChatGPT 아이콘 표시(출처는 `assets/SOURCES.md`). 상단 `AI 색상`에서 AI별 강조색을 고르고 저장하거나 기본색으로 되돌림. 밝은 색의 이름 글씨는 읽히도록 자동으로 어둡게 표시.
- **이어가기 요청 복사:** 작업 상세 맨 위 링크. 작업 폴더 경로·작업 ID·현재 상태·요청 첫 줄을 클립보드에 넣고, 수정 필요나 진행 중이면 어디서부터 할지 한 줄 덧붙임. Claude·Codex 채팅에 붙여 넣으면 그 작업 기록을 읽고 이어서 진행. 복사만 하며 파일은 바꾸지 않음.

## 실행

`dist/AIHub.exe` 더블 클릭 또는 `run.cmd`. EXE는 위쪽 폴더 중 `agent_lab`이 있는 곳을 작업 폴더로 자동 인식. 다른 위치로 옮겼다면 상단 `폴더 선택`으로 지정. 명령행: `AIHub.exe --root <작업 폴더>`.

## 화면

프로젝트를 먼저 고르고 그 안에서 작업과 결과물을 보는 구조. 왼쪽 탐색, 가운데 페이지, 오른쪽 미리보기.

- **왼쪽 탐색:** 홈 · 전체 작업 이력 · 파일 정리 · 프로젝트.
  - **홈:** 프로젝트 카드(작업 수, 파일 수, 최근 작업 날짜, 수정 필요 건수 — 0건도 표시)와 최근 작업 30건. 카드를 누르면 그 프로젝트로 이동. 카드는 최대 3열이며, 페이지가 좁거나 카드 글이 길면 모든 줄이 잘리지 않고 보이는 만큼만 열 수를 줄임.
  - **전체 작업 이력:** 모든 작업을 날짜별로 묶어 프로젝트 이름과 함께 표시. 아래의 AI별(Codex/Claude/ChatGPT/미상)·날짜별로 좁혀 볼 수 있음.
  - **파일 정리:** 미분류 파일 · 오래된 파일 · 점검 필요. `파일 정리` 자체는 90일 이상 수정되지 않았고 작업 기록에도 없는 파일을 먼저 표시.
  - **프로젝트:** 번호 프로젝트 폴더(`01_Dayline` 등)마다 한 줄(색인할 파일이 없는 빈 폴더도 표시). 번호를 뺀 이름과 작업 수 표시(원래 폴더 이름은 툴팁). 작업 폴더 바로 아래의 `output/`·`artifacts/`, 그 밖의 루트 폴더(예: `agent_lab`)와 루트에 놓인 파일을 다룬 작업은 `작업 폴더 직속` 한 줄로 묶음. 그 경로의 파일이나 폴더가 지금은 없어도 작업 기록에 경로가 남아 있으면 이 묶음에 표시. 파일 목록이 비었거나 작업 폴더 밖·임시 폴더(`tmp`, `.runtime`)·제외 폴더·없어진 번호 프로젝트 폴더만 가리키는 작업은 `프로젝트 미지정`.
- **프로젝트 페이지:** 제목 아래에 작업 수·파일 수·마지막 작업 날짜, 오른쪽에 `폴더 열기`. 탭 세 개.
  - **작업:** 그 프로젝트 폴더의 파일을 다룬 작업을 날짜별로 묶은 카드. 제목은 자르거나 줄이지 않고 카드 폭에 맞춰 필요한 만큼 줄을 바꿔 전부 표시, 아래에 상태·AI 역할·결과 파일 수(홈·전체 이력·AI별·날짜별에서는 프로젝트 이름까지). 이 줄도 줄이지 않고, 카드가 좁거나 역할이 길면 다음 줄로 넘겨 전부 표시. 작업이 어느 프로젝트에 속하는지는 작업 파일 목록의 경로(옮긴 폴더 대응 적용 후) 맨 앞 폴더로 정하므로, 결과 파일이나 그 하위 폴더를 나중에 지워도 프로젝트 폴더가 남아 있으면 작업은 그 프로젝트에 그대로 표시.
  - **결과물:** 문서(.md .txt .pdf .docx .pptx .xlsx .hwp .html .csv), 실행·배포 파일(.exe .apk .zip), 이미지·영상처럼 열어 볼 파일만 표시. `verification`·`tests`·`test`·`checks`·`check`·`history`·`records`·`record`·`logs`·`log`·`backups`·`backup`·`tmp` 폴더(대소문자 무시, 경로 어느 단계든)와 이름이 `-shots`로 끝나는 폴더는 제외.
  - **폴더:** 프로젝트 안의 폴더 트리와 파일 목록. 번호 프로젝트 폴더 안의 `output/`·`artifacts/` 하위 폴더는 각각 한 줄, 그 밖의 하위 폴더(예: 앱 소스)도 한 줄, 폴더에 바로 놓인 파일은 `(직속 파일)`. `tmp/`·`.runtime/`은 임시·접속 정보 공간이라 표시하지 않음. 폴더를 고르면 그 폴더(하위 포함) 파일만 목록에 표시.
  - **옮긴 폴더:** `agent_lab/path-aliases.json`(옛 위치 → 새 위치 목록)이 있으면 옛 경로로 적힌 작업 기록을 새 위치 파일에 연결해 파일의 AI·작업 크기·작업 상세 링크를 새 위치 기준으로 표시. 더 긴 옛 경로가 우선하며 대소문자는 구분하지 않음. 파일이 손상되었거나, 번호 프로젝트 폴더가 있는데 파일이 없으면 원래 경로로만 연결하고 `점검 필요`에 표시.
- **파일 목록(결과물·폴더 탭, 파일 정리, 검색, ChatGPT):** 종류·이름·AI·상태·크기·날짜. 머리글 클릭으로 정렬, 머리글 경계를 드래그해 모든 열 너비 조절(목록보다 넓으면 가로 스크롤). 조절한 너비는 설정에 저장되어 다음 실행에도 유지. Ctrl/Shift 클릭으로 여러 파일 선택.
  - **크기:** 파일은 파일 크기, 작업은 task.json 파일 목록 중 현재 남아 있는 결과 파일 크기 합계(EXE가 포함된 작업은 수십 MB), 대화는 메시지 텍스트 크기. 정렬은 바이트 수 기준.
  - **상태 색:** 작업 행 왼쪽의 4px 띠와 상태 열의 칩으로 표시. 완료(검토 통과 포함) 초록, 진행 중 노랑, 검사 통과 파랑, 수정 필요 빨강, 미상 회색. 작업에 연결된 파일은 가장 최근 연결 작업의 상태 색, 미분류 파일과 대화는 색 없음. 목록 위에 범례 표시. 작업 카드는 같은 색을 상태 표시 하나에만 사용.
  - **열 구분선:** 열과 열 사이에 셀 높이 절반 정도의 옅은 회색 세로선(머리글 포함). 가로선과 셀 테두리는 없음.
  - **커서 위치:** 행 배경은 흰색이고 커서가 올라가도 상태 띠는 그대로 보임. 선택한 행은 선택 색(연보라) 유지.
- **오른쪽 미리보기:** Markdown, 텍스트·코드, JSON(정렬), 이미지, PDF(앞 5쪽 텍스트), 작업 상세.
  - **작업 상세 순서:** `이어가기 요청 복사` → 요청 원문 → 결과 파일(없어진 파일은 `현재 없음`) → 검사와 검토(상태, 검사·검토 횟수, AI 역할, 단계별 AI와 모델 한 줄 요약) → 목표 · 완료 기준 · 검사 명령. 단계별 로그 파일 링크와 메모는 접혀 있고 `단계별 로그 보기`를 누르면 펼쳐짐(다시 누르면 접히고, 다른 작업을 고르면 접힌 상태로 시작).
- **검색:** 입력하면 파일 경로와 작업 요청·목표를 바로 검색해 파일 목록으로 표시. `파일 내용 포함`을 켜고 Enter를 누르면 1MB 이하 텍스트 파일 내용까지 검색. 검색어를 지우거나 왼쪽 탐색을 누르면 보던 페이지로 복귀. `Ctrl+F` 검색, `F5` 새로고침.
- **열기:** `기본 앱으로 열기`, `폴더 열기`. 실행 파일·스크립트(.exe, .cmd, .ps1, .py 등)는 실수로 실행되지 않도록 기본 앱 열기를 막음.

## 파일 관리

파일 목록에서 하나 이상 선택 후 **우클릭** 메뉴에서 선택. 키보드 단축키는 없음.

- **복사… / 이동…:** 대상 폴더를 고른 뒤 확인 창에서 실행. 같은 이름 파일이 있으면 덮어쓰지 않고 `이름 (2).확장자`로 저장. 새 파일은 배타적으로 만들어, 이름을 고른 직후 다른 프로그램이 같은 이름을 만들어도 덮어쓰지 않고 다음 이름을 사용. 복사가 실패하면 이번 작업이 만든 파일만 지움.
- **휴지통으로 삭제:** Windows 휴지통으로만 보내며 휴지통에서 복원 가능. 휴지통으로 보내지 못하면 파일을 그대로 두고 실패로 알림. 영구 삭제 기능은 없음.
- 확인 창은 기본 버튼이 `취소`라서 Enter만으로는 실행되지 않음. 작업 기록과 연결된 파일을 이동·삭제하면 해당 작업 화면에서 `현재 없음`으로 바뀐다는 경고를 표시.
- `agent_lab/jobs` 작업 기록과 실행 중인 `AIHub.exe`는 변경 거부. 작업 기록 폴더로의 복사·이동, 이미 대상 폴더에 있는 파일의 이동도 건너뜀.
- 실행 후 다시 색인하고 보던 위치(프로젝트 탭, 폴더) 유지(폴더의 마지막 파일을 옮기거나 지워도 그 폴더가 남아 있으면 그대로 선택). 결과(완료·건너뜀·실패)는 상태 표시줄과 알림 창으로 표시.

## 오래된 파일

왼쪽 `파일 정리` 아래의 `오래된 파일`에서 90일·180일·1년 이상 **수정되지 않은** 파일과, 그중 작업 기록에 연결되지 않은 90일 이상 파일을 오래된 순으로 표시. 개수와 총 크기도 표시.

판단 근거는 마지막 수정 시각. 마지막으로 연 시각(접근 시각)은 이 앱의 미리보기, 백신 검사, OneDrive 동기화만으로도 바뀌어 "사용하지 않음"의 근거가 되지 못함. 실제로 필요 없는 파일인지는 직접 확인 필요.

## AI 구분 근거

- **작업:** `agent_lab/jobs/*/manifest.json`의 `implementer`를 구현자로 표시. 단계 폴더의 `*.model.json`(provider·model)이나 history의 `provider`를 계획·검토·조사 담당으로 표시. 검사 단계는 `로컬`로 표시.
- **파일:** 작업의 `task.json` `files`에 정확히 같은 경로가 있을 때만 그 작업의 AI를 붙임. 근거가 없으면 `미분류`로 두고 추측하지 않음. 프로젝트 페이지의 작업 목록과 폴더 탭의 "관련 작업"은 그 폴더 안의 파일을 다룬 작업이 있다는 뜻일 뿐, 폴더 전체를 그 AI가 만들었다는 근거는 아님.
- **ChatGPT:** 웹 대화는 로컬에 기록이 없음. 이름에 `chatgpt`가 있거나 `gpt`와 `prompt`가 함께 있는 .md/.txt 파일을 ChatGPT용 프롬프트로 표시. 실제 대화는 ChatGPT 설정 → 데이터 제어 → 데이터 내보내기로 받은 zip(또는 `conversations.json`)을 `ChatGPT 내보내기 열기`로 지정하면 표시. 화면에 보이던 분기만 표시.
- 손상되거나 필드가 없는 기록은 `미상`과 `점검 필요`로 표시.

## 스캔 범위

`output/`·`artifacts/`의 직속 파일과 하위 폴더 전체, 번호 프로젝트 폴더(`01_…`)의 같은 구조와 그 밖의 하위 폴더·직속 파일, 그리고 작업 파일 목록이 가리키는 최상위 폴더(예: `agent_lab`, jobs 제외). `tmp`, `.runtime`, `node_modules`, `.venv`, `.git`, `__pycache__`, `.build`, `.next` 등은 제외. 프로젝트당 최대 3000개 파일까지 표시하며 넘으면 `점검 필요`에 표시.

## 저장 위치

앱 자체가 쓰는 파일은 설정(마지막 작업 폴더, ChatGPT 내보내기 경로, 목록 열 너비, AI 강조색)만 `%LOCALAPPDATA%\AIHub\settings.json`에 저장. 내보내기 파일은 복사하지 않고 경로만 기억.

## 개발 · 재빌드

Windows 10/11 64비트, Python 3.13 기준. 새 가상환경을 만들어 `requirements-build.txt`(PySide6-Essentials 6.12, PyInstaller 6.22, pypdf 6.21)를 설치.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe app.py --root <agent_lab이 있는 작업 폴더>
.\.venv\Scripts\python.exe -X utf8 build.py
.\.venv\Scripts\python.exe -X utf8 verify.py
```

원래 작업 폴더 안에서는 같은 버전이 설치된 Dayline 가상환경(`..\..\01_Dayline\dayline\.venv\Scripts\python.exe`, 예전 구조는 `..\dayline\.venv`)을 그대로 사용 가능하며 `run.cmd`도 이 순서로 찾음. `verify.py`의 실제 작업 폴더 검사는 상위 폴더 중 `agent_lab`이 있는 곳을 대상으로 하므로, 저장소만 따로 받은 경우에는 상위에 `agent_lab`이 있어야 통과.

`verify.py`는 유닛 테스트 후 `dist/AIHub.exe --smoke-test`를 offscreen·Windows 네이티브로 실행. 임시 픽스처(Codex 구현/Claude 검토, Claude 구현/Codex 검토, 손상 기록, ChatGPT 내보내기 zip, 번호 프로젝트 폴더와 옮긴 경로 대응표)로 화면 동작과 둘러보기 중 파일 불변을 확인한 뒤, 같은 픽스처에서 크기 정렬·오래된 파일·우클릭 메뉴의 복사·이동·휴지통 삭제(가짜 휴지통으로 대체)·단축키 미등록·보호 경로·확인 창 취소를 검사하고, 실제 작업 폴더도 읽기 전용으로 열어 파일 상태가 그대로인지 비교. 결과는 `verification/`에 기록. EXE가 소스보다 오래되면 실패 처리. Windows 네이티브 검사 창은 포커스를 가져가므로, 검사 중에는 실제 키보드·한글 입력·마우스 버튼 입력을 막고(커서 이동은 허용, 차단 여부도 검사) 사용자가 그동안 입력해도 결과가 바뀌지 않게 함. 커서 위치 행 색 검사는 실제 마우스 커서를 움직이지 않고 창에 마우스 이동을 전달해 확인(다른 창이 앞에 있어도 동작). 다른 프로그램이 같은 시각에 작업 폴더 파일을 바꾸면 실제 작업 폴더 비교는 실패할 수 있음.

## 한계

- 현재 데스크톱 채팅(Codex/Claude 앱) 대화 기록 자체는 읽지 않음. agent_lab을 거치지 않은 작업은 미분류.
- 파일 변경 자동 감지 없음. `새로고침`(F5)으로 다시 색인.
- PDF는 텍스트만 표시. 서명하지 않은 개인용 빌드.
- 자동 검사는 실제 Windows 휴지통을 쓰지 않음(검사할 때마다 휴지통이 채워지지 않도록 가짜 휴지통 사용). 실제 휴지통 이동은 Qt `QFile.moveToTrash`가 담당.
- 폴더 단위 복사·이동·삭제와 실행 취소(Undo)는 없음.
